============================================================
一、文件目的
============================================================

本文件整理新版使用者問卷的題目架構、欄位分層、症狀 features、
32 個文獻候選 features，以及前端、Power Automate、Excel 與後端模型
之間應如何配合。

本次更新採取「先蒐集、後切換模型」策略：

1. 新版問卷先開始蒐集症狀與候選欄位。
2. 新資料先寫入研究 Excel，供資料品質檢查及新版模型訓練。
3. 現行模型 HTTP 仍只接收既有 ai_api_feature_row。
4. 新模型完成欄位凍結、驗證與版本發布後，才切換到新版推論契約。

此策略可避免前端先加入新欄位後，直接造成現行模型 API 欄位錯位、
型別錯誤、422 回應或模型輸入語意與訓練資料不一致。

============================================================
二、新版問卷整體架構
============================================================

目前程式共有 54 個題目定義，其中包含知情同意與 Email。
實際受試者看到的題數會依性別、個人病史、家族史與症狀選項動態改變，
不會要求每位使用者回答全部 54 題。

模組與題目數如下：

1. 知情同意：1 題
2. 基本資料：6 題
3. 近期症狀：13 個主題組，加上最多 4 個條件式追問
4. 女性相關資訊：6 題，僅女性路徑顯示
5. 菸草與環境暴露：8 題
6. 心理健康：3 題
7. 飲食習慣：5 題
8. 個人病史與家族史：7 題，其中部分為條件式題目
9. 聯絡資料：1 題

主要條件式跳題：

1. 乳房與婦科症狀只在女性路徑顯示。
2. 男性生殖系統症狀只在男性路徑顯示。
3. 女性月經、生育、哺乳、抹片及荷爾蒙題只在女性路徑顯示。
4. 只有曾抽菸者會看到戒菸狀態。
5. 只有曾被診斷癌症者會看到癌別複選題。
6. 只有一等親有癌症史者會看到家族癌別複選題。
7. 只有選取肝病者會看到肝病病因細分。
8. 只有選取特定症狀者會看到頻率或持續時間追問。

============================================================
三、症狀題目的設計原則
============================================================

新版症狀題目不再對所有症狀套用相同的「持續兩週」條件，而是依症狀
性質分為三類。

第一類：單次發生也應記錄的警示狀況

例如吐血、咳血、血便、黑便、肉眼血尿、性交後出血、經間出血、
停經後出血、新出現腫塊、睪丸或陰囊腫大及尿滯留。

這些狀況在最近三個月內即使只發生一次，也應勾選。原因是若要求症狀
持續兩週，會錯誤排除一次性但重要的警示訊號。

第二類：持續、反覆或明顯新發生的一般不適

例如腹痛、消化不良、胃酸逆流、火燒心、耳痛、鼻塞、關節疼痛及
骨骼疼痛。

這些症狀較常見且非特異，因此要求使用者選取「持續、反覆或明顯新發」
的情況，以降低偶發小不適造成的雜訊。

第三類：必須由醫療人員確認的診斷或事件

例如深層靜脈栓塞／肺栓塞、慢性胰臟炎、口腔黏膜下纖維化及肝病病因。

這些項目移到病史區，不要求使用者自行判斷疾病。骨折目前暫定詢問
過去 12 個月，最終回溯期間仍須由模型負責人與臨床審查確認。

共同作答規則：

1. 明確選取症狀：feature = 1。
2. 明確選取「以上皆無」：該題組 features = 0。
3. 選取「不確定」：該題組 features = null／空白，不可寫成 0。
4. 因性別或條件跳題而未顯示：狀態為 not_applicable，不可寫成 0。
5. 「以上皆無」與「不確定」皆與其他選項互斥。

這樣設計的原因是「沒有症狀」、「不知道」與「題目不適用」在模型與
研究上是三種不同資料狀態，若全部編碼為 0，會產生系統性標註錯誤。

五、症狀頻率與持續時間研究欄位
============================================================

以下追問不直接改變主要二元症狀欄位，而是保存在研究 metadata：

research_testicular_pain_pattern：睪丸疼痛為一次、反覆或持續
research_sore_throat_pattern：喉嚨痛為一次、反覆或持續
research_head_neck_mass_pattern：頭頸腫塊少於六週或間隔六週以上仍存在／再發
research_visible_hematuria_pattern：肉眼血尿為一次或反覆兩次以上

保留獨立 metadata 的原因：

1. 文獻顯示部分症狀第一次與再次就診可能有不同訊號強度。
2. 目前尚未確認新版模型是否把頻率當成獨立輸入。
3. 若直接把頻率混入原本的 0/1 欄位，會破壞既有資料語意。

============================================================
八、120 個模型特徵與 71 欄 API 契約的差異
============================================================

目前使用者介面顯示「120 模型特徵」，這是模型團隊提供的模型建置描述。
但目前程式實際送往現行 API 的 ai_api_feature_row 只有固定 71 欄。

此外，前一版問卷另有 55 個症狀研究欄位，以及 processed_meat 研究欄位。
新版症狀研究欄位增加到 82 個，並另輸出 32 個候選欄位向量；32 個候選
欄位大多同時存在於 82 個症狀／病史欄位中，因此不可把各層數量直接相加
當成最終模型 features 數。

後端模型團隊必須提供正式 manifest，釐清：

1. 所稱 120 個 features 的完整名稱。
2. 120 個 features 的固定順序。
3. 120 個 features 是否包含症狀欄位。
4. 是否包含 missing flags、label、score、record_id 或 data_source。
5. 加入 32 個候選欄位後，是取代、拆分、衍生或新增。
6. 新版最終 feature count 是否為 152，不能僅以 120 + 32 推定。

在這份 manifest 完成前，平台不可宣稱新版模型已正式使用全部新增 features。

============================================================
十、目前前端送出資料的物件分層
============================================================

ai_api_feature_row：
現行 71 欄模型 HTTP 輸入。新模型尚未發布前不可改成其他物件。

optimized_feature_row：
現行 71 欄舊版結構化資料，保留作為相容與稽核比較。

symptom_feature_row：
82 個症狀研究欄位。1 代表選取、0 代表明確無、null 代表未知或不適用。

symptom_answers：
保存題組、中文名稱、英文名稱、回答狀態及使用者選取的症狀。

vnext_feature_row：
固定 32 欄候選向量，供新版模型訓練、比對及後續契約凍結。

vnext_feature_metadata：
保存症狀頻率及持續時間追問，不送入現行模型。

research_feature_row：
保存 processed_meat 等尚未納入正式模型的研究欄位。

excel_row：
研究 Excel 的完整去識別化寬表資料，不包含 Email。

contact_row：
受限權限聯絡資料表使用，只保存 record_id、Email、時間及語言。

data_quality：
保存缺失欄位及前後矛盾警告。

============================================================
十一、Power Automate 與 Excel 應如何配合
============================================================

1. 「收到 HTTP 要求時」與「剖析 JSON」應使用新版 transitional schema。
2. 研究 Excel 的執行指令碼參數維持：

string(body('剖析_JSON')?['excel_row'])

3. 聯絡 Excel 的執行指令碼維持：

string(body('剖析_JSON')?['contact_row'])

4. 現行模型 HTTP body 必須維持：

body('剖析_JSON')?['ai_api_feature_row']

5. 研究 Excel 已新增 36 個欄位，包含 32 個候選 features 與 4 個研究追問。
6. Excel Office Script 應依表頭名稱配對 JSON key，不應依欄位位置硬編碼。
7. JSON null／undefined 應寫入空白，不可寫成 0。
8. Power Automate 不應自行猜測缺失值或重新計算 features。
9. 模型 HTTP 成功後才進入報告寄送；失敗時應記錄狀態並停止寄信。

資料庫與正式產品遷移。

二、復發次數欄位

後端定義 16 個最近 180 天內的 repeat_count 欄位，範圍為 0 至 9。只有母症狀

不得把單次症狀視為復發。

部分腫塊及口腔症狀另需記錄兩次事件的最短間隔天數，至少 42 天才視為兩次
獨立事件。

三、不增加問卷即可完成的後端工作

後端可先實作 12 項 FIELD_ALIAS 或衍生規則，包括糞便潛血、糖尿病史、糖尿病
惡化、噁心、背痛、憂鬱史、感染、下泌尿道症狀、腹痛、廣義腫塊、泌尿道感染
近似值及抹片在期狀態。依後端規格，完成此層可使可運作規則由 53/96 提升為
69/96，且不增加使用者題目。
